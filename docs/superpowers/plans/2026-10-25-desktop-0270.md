# 0.27.0: the desktop app updates itself and runs the event service — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- The desktop app keeps itself current with one click.
- It runs the event service without a terminal, and brings the service back after a crash but never after a stop.

**Architecture:**
- **Updater:** already built (`updater.rs`). Turning it on is a key on the owner's Mac and its public half in
  `tauri.conf.json` (Task 4, the lead's).
- **Event service:**
  - A new Rust module, `event_service.rs`, starts `<data>/launch/events-daemon run` detached, through DA4's launcher
    and pins, with its output in a capped log. It records what it started in the app's settings directory.
  - A pure decision function, driven by a 15 s watchdog, chooses start, adopt, restart or leave stopped.
  - `events-daemon` gains one thing: a clean-stop marker. It is how the app tells a stop from a crash when the service
    is not its child (Task 1).
  - The window gets a switch, status lines and three dialogs (Task 3).

**Tech Stack:** Tauri 2 (Rust), React 19 with `@cueplusplus/ui` 0.29.0 (today's look: the redesign is 0.28.0), Vitest,
Node's test runner for `events-daemon`.

**Spec:** `docs/superpowers/specs/2026-10-24-desktop-0270-design.md`: D1, D2, D4, D5, D6, D8 and D9 (as amended below),
and §7.

## Decisions this plan adds (lead's calls, 2026-10-25)

- **P1. D8's question needs no rule count.**
  - **Why:** whether collection is on, and how many rules are enabled, is answerable only by a running service
    (`status` reads it through the control socket, and the pause lives in its database). So the app cannot know them
    before the first start.
  - **The rule instead:** the first automatic start asks once whenever `<state>/events/events.sqlite` already exists.
    The question is "The event service has run on this Mac before. Starting it resumes whatever it was set to do.",
    with **Start** and **Not now**. On a fresh Mac it starts silently.
  - The answer is kept, and the question is never asked again.
- **P2. A clean stop leaves a marker.** D4 says the app watches its own child's exit. After the app restarts, the
  service it started earlier is no longer its child, so a clean stop cannot be told from a crash.
  - `events-daemon` writes `<state>/events/last-stop.json` (`{"version":1,"pid":…,"at":"<ISO>"}`) when its owner
    stops cleanly.
  - The app reads it when a service it started (by its record) disappears and is not its child. A marker for that PID
    newer than the service's start means it was stopped; otherwise it crashed.
  - This touches `events-daemon` but not Appendix A of the events design.
- **P3. The quit question is asked in the window,** with cue-ui's `AlertDialog`, not a native dialog. That adds no
  plugin.
  - Quit, from the tray or Cmd+Q, shows and focuses the window, then asks.
  - Asked only when a service the app started is running, and no answer is remembered.

## Global Constraints

- **The launcher and pins:** the service is started as `<data>/launch/events-daemon run`, with the same pins and
  environment as every other call (DA4, `runner.rs`). No shell. Never `npx`.
- **Detached:** the service runs in its own process group, so it outlives the app. Its stdout and stderr go to
  `<state>/events/service.log`. That file is kept under 1 MB: when a write would pass it, the older half is dropped.
- **The app never approves anything** and never opens the event database. It reads only whether `events.sqlite`
  exists, and the `last-stop.json` marker.
- **The watchdog:** `agent-events status` every 15 s while the app runs.
  - It restarts only a crashed service the app started, waiting 1 s, 5 s, then 30 s between tries.
  - After 5 failed starts within 10 minutes it stops trying.
- **Windows:** the switch is absent, with the line "The event service doesn't run on Windows yet." (B1-G).
- **A recorded PID** is ours only if the process with that PID is still `events-daemon run`, checked by its command
  line. A reused PID is never adopted or stopped.
- **Copy, exactly:**

| Where | Text |
|---|---|
| Events switch | "Run the event service" |
| A restart | "Restarted <relative time>" |
| A stop from outside | "Stopped from outside at <time>" |
| Giving up | "The event service stopped 5 times in 10 minutes, so Agent Comms stopped restarting it.", with **Try again** |
| An older adopted version | "A newer event service is installed (<version>).", with **Restart to use it** |
| First start | the title "Start the event service?", the body as in P1, and **Start** and **Not now** |
| Quit | the title "Keep the event service running?", the body "It keeps watching your accounts after Agent Comms quits.", **Keep running** (the default) and **Stop it**, and a checkbox "Remember my answer" |
| Full Disk Access | "Events from WhatsApp need Full Disk Access for Agent Comms.", with **Open System Settings** |

- **Today's look:** cue-ui 0.29.0 components and the `cue-ui` skill's rules. No new look: that is 0.28.0.
- **Run `pnpm verify`** before saying anything works. Never send mail, post or touch a real account.

## Review Focus

1. **A terminal's `agent-events run` already owns the database when the app starts it.** The second owner is refused,
   and the app must adopt the running service, not restart in a loop.
   - Test: `decide` given "start failed: already running" plus a status of running → `Adopt`.
2. **A service that dies at once,** from a bad Node or a broken runtime, must back off and give up, never spin.
   - Test: five `ChildExited{code: 1}` within 10 minutes → `GiveUp`, and the waits are 1 s, 5 s and 30 s.
3. **A reused PID.** The recorded PID now belongs to another program, which must not be adopted or stopped.
   - Test: `is_our_service(pid)` is false for a PID whose command line is not `events-daemon run`.
4. **The log grows without bound** over weeks of running.
   - Test: `append_capped` with 1.2 MB in a 1 MB cap leaves at most 1 MB, ending with the newest bytes.
5. **Quit with the window hidden, or Quit pressed twice.** The dialog must show once, in front, and the second Quit
   must not quit past it.
   - Test: the UI test sends `quit-requested` twice, sees one dialog, and Keep running calls `answer_quit` once.

### Task 2: the app's event-service supervisor (Rust)

**Files:**
- Create: `apps/desktop/src-tauri/src/event_service.rs`
- Modify: `allowlist.rs` (an `EventsStop {}` call, `agent-events stop --json`, shape `Bare`), `commands.rs`, `lib.rs`
  (the module, its state, the watchdog started in `setup`), `window.rs` and `tray.rs` (quit interception), `build.rs`
  and `capabilities/default.json` (the new commands), `ipc.rs` (the types below)
- Test: unit tests in `event_service.rs`; `commands.rs`'s command-count test (`NAMES.len()` goes from 14 to 21)

**Interfaces:**
- **Produces, the IPC types** (`ipc.rs`, serialised camelCase):

  ```rust
  pub enum EventServiceStatus { Unavailable, Stopped, Starting, Running, GaveUp }
  pub struct EventServiceState {
      pub available: bool,                 // false on Windows
      pub wanted: bool,
      pub status: EventServiceStatus,
      pub started_by: Option<String>,      // "app" | "terminal"
      pub since: Option<String>,           // ISO
      pub version: Option<String>,         // e.g. "0.27.0" (from the launcher's .current at start)
      pub newer_version: Option<String>,   // set when the installed version differs from the running one
      pub restarts: u32,
      pub last_restart_at: Option<String>,
      pub stopped_from_outside_at: Option<String>,
      pub log_tail: Vec<String>,           // last 20 lines, only when GaveUp
      pub first_start_question: bool,
      pub full_disk_access: String,        // "granted" | "missing" | "not-needed"
  }
  ```

- **Produces, the commands** (all `async`, through `blocking`, never on the main thread):

| Command | Returns |
|---|---|
| `event_service_state()` | `EventServiceState` |
| `set_event_service(on: bool)` | `EventServiceState` |
| `event_service_retry()` | `EventServiceState` |
| `restart_event_service()` | `EventServiceState` |
| `answer_first_start(start: bool)` | `EventServiceState` |
| `open_full_disk_access()` | `()`, opening `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles` |
| `answer_quit(keep: bool, remember: bool)` | `()`, then quits |

- **Produces, the events:**
  - `event-service:changed`, with the new state, whenever it changes;
  - `quit-requested`, when Quit is pressed and P3 says to ask.
- **Produces, the pure decision function, the heart of the task and fully unit-tested:**
  `decide(record: &ServiceRecord, observed: &Observation, now: SystemTime) -> Action`.
  - `Action` is one of `Start`, `Adopt`, `Restart { after: Duration }`, `MarkStoppedFromOutside`, `GiveUp`,
    `RestartForVersion`, `AskFirstStart` and `Nothing`.
  - `ServiceRecord` is persisted as `<app settings dir>/event-service.json`: `wanted`, `pid`, `started_at`,
    `version`, `started_by_app`, `first_start_answered`, `quit_answer` and `recent_failures` (timestamps).
  - `Observation` holds the status's `owner`, the child's exit if the process is ours, the marker if present, whether
    the database exists, and the launcher's current version.
- **Consumes:** `runner.rs`'s program and environment construction for a launcher, `launchers::find_launcher`, and
  `settings::settings_dir`.
